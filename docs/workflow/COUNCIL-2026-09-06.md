# Council review — 2026-09-06 — the family design as drafted

Six lenses, three rounds, full transcripts at
`ai_working/council-converge-family/round1/*.md` and `round2/ALL-SIX.md`.

**Verdict: FAIL 4 · CONCERN 2 · PASS 0 — with unanimous agreement that the
direction is right and every defect has a cheap fix.**

## Blockers (as the council stated them)
- **B1** Three of five `family.toml` rows name repositories that return 404
  (`-service`, `-app`, `-agent-types`); family.v1's own kit is unsatisfiable on day one.
- **B2** The head of the family fails its own method's documents kit (service.v1 at
  105 lines; no participant kit; README claims a ledger that does not exist).
- **B3** Nothing is real: zero readers of `family.toml`; no run record has flowed.
- **B4** The merged-gate (service.v1 Core 4) is forgeable in seconds: an empty commit +
  `command: "true"` + a merge-base computed in a repo the attacker supplied. Run and
  manager session are two records with no edge, so "a check by its manager" cannot be
  validated.
- **B5** Ratifying service.v1 Core 1+3 as drafted would make the steward's five shipped
  writes (decision · feedback · priority · steer · ask) defects — six records with a
  home for one and a half of them.

## Answers the council converged on
- **Seams (Q1):** don't stand up three empty repos. Build the service inside the method
  repository where `app/`, `ledger/` and a booting FastAPI already live; extract when a
  second consumer exists ("extraction after the seam is proven is a week, un-extraction
  a quarter"). Delete `converge-queue` as a part (the tracker is already a checked
  install dependency, not a Converge project). `service` + `agent-types` are one
  lifecycle — do not split before it is written. `converge-app` is the largest hidden
  cost (6,399 lines, `data.py` reads `ledger/rows.yaml` directly, 521 lines of tmux).
  **Correction to the record:** the launcher/watchdog scripts live in the Amplifier CLI
  package — a sixth repository the registry does not name and family.v1 Core 4 forbids
  depending on.
- **"The API is the truth" (Q2):** right seam — a deletion of seven stores into one, not
  a centralisation; makes the repo split *more* optional. Dissent on order (Brian:
  "a promise of a subtraction"). The `agent-types.v1` seam the synthesis called for was
  never drafted.
- **service.v1 over-specifies (Q3):** unanimous. Delete Core 8 (the app polls
  deliberately, with a measurement on record — no SSE exists); delete Core 11's tick
  and maintained quiet/silent state (a hedge becoming a record is a lie); freeze only
  `run` and `check`, move the other four records to "does not freeze"; replace the
  free-text "what it printed" with scalars (closes a token-exfiltration path).
- **Verification when the manager is BYO (Q4):** Core 4 is NOT sufficient and the
  panel's own hardening was broken by execution. Required: the run↔manager edge; a
  manager-scoped token tier; `merged` as *request or report*; the contract must state
  what the gate does NOT prove; a third answer "could not check" that never collapses
  to false; the agent type — not the service, never the steward — notices liveness.
- **"A run is a record" (Q5):** honest only if liveness is an *observation* with a
  timestamp, not a maintained state; a `kill -9` must yield an observation row.
- **First adopter trips over (Q6):** three 404s; "one install command" (composition.v1
  Core 5, FROZEN) never explained for five repos; picker copy in the forbidden
  register (`launch_lane.sh` on a screen); no status word for "named but absent"; the
  steward's OWN project not on the picker; a contract collision with experience.v1
  Core 1/2 (anchor is a manager session; two places only) with no candidate filed.
- **Month two (Q7):** two custody clocks on one claim (delete four words: the tracker
  owns custody, the service records it read-only); eleven of fourteen method contracts
  govern a body scheduled to leave; family.v1 Core 7 makes the steward the bottleneck
  on every seam change; the lockfile question; `<part-id>` vs `<project-id>`; budgets
  promoted only by the person being hurt.

## Recorded dissent (the steward's to settle)
- **D-1** a `planned` status word vs deleting the three rows.
- **D-2** may the service READ the world to REFUSE a write but never to MANUFACTURE a
  record (Brian's line) — with total-host-death as the one named exception.
- **D-3** should the picker exist at all, or does Direction already show the parts?
- **D-7** the direction change itself was never put to the steward: the method's FROZEN
  vision (principle 10 "Converge is the method, not the project"; non-goal "own the
  tooling worker sessions run on") has no candidate beside it, so every tooth drafted
  this week sits on an unratified premise.

## Lift conditions (summary)
No 404 rows; service.v1 under 100 lines at ≤6 teeth, kit green; Core 8/11 gone; Core 4
carries its "does not prove" sentence and cites operation.v1 Core 7; one run record
flows end to end through the app that already boots and the three break-tests
(`POST /runs` without a liveness handle refused; `kill -9` → observation row; empty
branch + `command:true` + `merged` refused) are pasted; a five-row table mapping the
steward's five writes to records or owning parts; a success bullet with a person and a
number in it; and a VISION candidate on the method repo for the direction change.
