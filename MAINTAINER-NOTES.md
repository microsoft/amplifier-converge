# Methodology repository transition

## Working destination

One focused repository, microsoft/amplifier-converge, carries two layers:

- Shared vision and contracts for people and agents.
- Practical guides for applying and reviewing the method in different environments.

This branch prepares that destination. It replaces the umbrella's application plans and component-specific contracts with methodology guidance. The original source checkouts and all remote repositories remain unchanged.

## Decisions from this review

| Existing area | Direction for the new methodology |
| --- | --- |
| Method | Consolidate its portable concepts here, with one home for each promise. |
| App | Omit the application. Preserve attention, authorship, feedback, and evidence lessons in the relevant contracts. |
| Reader | Omit the standalone component. Preserve understandable document changes and review in Shared direction. |
| Sessions | Consolidate continuity into Execution and recovery. Require a suitable continuation or recovery mechanism without prescribing a runtime. |
| Service | Preserve durable authoritative records, checked changes, and safe retries. Do not retain its implementation for speculative reuse. |
| Queue | Apply durable assignments, ownership, dependencies, and safe recovery in Execution and recovery and the agent guide. No particular queue implementation is required. |
| Agents and operating bundles | Extract useful execution practices. They are not dependencies of this methodology; disposition of existing implementations is outside this change. |
| On-ramp, Direction, Operation, Experience SDK | Carry portable lessons where relevant. Application tools and host integration are outside this repository's required structure. |

**Legacy repository retirement belongs to Brian. Do not archive, delete, retire, or modify the old repositories as part of this work.** No separate reuse archive is requested. The map records concept destinations, not completed repository migrations.

## Review and adoption

The files are a review edition. Existing projects retain their own agreements until their authorized owners adopt a revision. The review Page was the source of the core documents; this branch is the repository-shaped proposal. Reconcile further Page edits before adoption rather than maintaining two governing copies.

The three guides are practical entry points, not additional law. Their examples may change without changing the contracts. A new capability or integration can have a focused repository if it develops a coherent, independently useful responsibility.

Review the vision first, then each contract and its linked guide. Resolve any substantive disagreement before treating the revision as the accepted methodology. This does not require a new approval for ordinary preparation, editorial fixes, or implementation choices within existing authority.
