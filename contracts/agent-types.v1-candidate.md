# Agent Types Contract — v1 candidate (proposal)

**Target.** `contracts/agent-types.v1.md`, Core 5 (a person can attach).

## The exact change
Before:
```
5. **A person can attach, and a session survives.** Every type that runs in a
   terminal names the mechanism by which a person attaches to the live session —
   from the app, and from a terminal if they choose — and by which the session
```
After:
```
5. **A person can attach, converse with a manager, and a session survives.** Every
   type that runs in a terminal names the mechanism by which a person attaches to a
   live session (a read) and, for a manager run only, converses with it from the
   desk's console (a write, recorded as a *steer*) — from the app, and from a
   terminal if they choose — and by which the session
```

## The evidence
Transcript (403) "Conversation becomes a modality, not a place"; (783) "we'll call it
manager console"; (843) "an actual pane that when active just remains in place." The
agents part's ratified clause 7 — "Attaching is a read, never a write" — permits
watching and forbids the console. A UI copilot as an agent type stays deferred on the
steward's own word (853) and is recorded as such in desk.v1.

## What does NOT change
Cores 1–4, 6; the three-functions shape; liveness as observation.
